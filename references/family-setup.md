# 首次设置与个性化推算

首次启动且当前私有档案不存在 `FAMILY-profile.json` 时，必须提醒用户自定义孩子及家庭成员信息。先吸收用户已经提供的资料，再集中询问缺项，不把初始化变成每次报告的重复问卷。

可直接这样提示：

> 首次使用，请设置家庭信息，之后我会按每次会议的实际日期自动推算孩子年龄、入学时长和年级：孩子的代号、生日（或截至某日的年龄）、入学日期及当时年级（或截至某日的当前年级）、每年升年级日期和学制；家庭成员的称呼、与孩子的关系、通常参与会议的人，以及私有档案保存位置。称谓或性别信息可按需要补充，不需要真实姓名。暂不愿提供的项目可以留空。

## 保存与复用

- 使用 [空配置模板](../assets/family-profile-template.json)，只将用户提供或确认的资料写入私有档案的 `FAMILY-profile.json`。不写入技能安装目录或公开仓库。
- `children` 支持多个孩子，每人一个稳定 `id`；报告必须明确目标孩子。`family_members` 每项可用 `{id, alias, relationship_to_children}`，其中关系按孩子 id 记录，例如 `{"child-1": "爸爸"}`。`default_participants` 保存家庭成员 id；当晚参与者以当前材料为准，不将默认爸爸套用到妈妈或其他照顾者。
- 只收集解释角色及计算所需的信息；不索要真实姓名、证件、住址、学校全名等。成年家人的生日不是必要字段。
- 用户只想临时分析或不愿保存时，在当前会话使用已提供资料，未知项标注未知；初始化提醒仍须给出，但不能因此阻止能够完成的分析。不凭空创建已确认资料。
- 后续优先读取配置，仅在缺项影响判断、出现冲突或用户要求修改时询问。生日校正可直接更新，学籍变动保存为新生效日期的基准，保留旧基准用于历史报告。保存时保留未知兼容字段、使用临时文件替换，失败保留旧文件并说明。

## 年龄、入学时长与年级

- 有生日：按原始会议日期计算周岁、完整月数；周/月/年报用报告期末日期。不要用今天替代历史日期。
- 只有年龄：保存 `age_reference: {as_of, years, months}`。截至日期之后可推算约龄，明确“约”；不能反推一个虚构生日或假装精确到天。早于年龄基准的历史资料标注年龄待确认。缺少月份时注明精度限制并请家长补充，不把“6岁”当作精确“6岁0个月”。
- `school_start` 为用户明确的入学日期，入学当天已过 0 天；入学前给出距离入学天数。
- 每条 `school_baselines` 含 `effective_date`、`grade_index`、`promotion_day`、`stages`。`grade_index` 是在自定义学段序列中的累计年级，从 1 开始；例如小学 6 年、初中 3 年时，初中一年级是 7。每条基准保存当时完整规则，后续修改不改变之前的历史。
- 原版“入小学一年级、每年 9 月 1 日升级”的逻辑保留为可选设置：向用户说明后，由用户确认自己的入学日期、年级与学制。不能把示例或原作者家庭资料当成默认事实。
- 用不晚于报告日期的最近基准，加上跨越的升年级边界数推算；学段名称及年数使用用户确认值。升年级日期必须每年存在（例如 09-01、08-20；不接受 02-29）。年级须标明“按已确认规则推算”，不是学校实际在读证明。
- 留级、跳级、转学制时由家长提供新的生效日期与累计年级。不得自行假定变化。早于首个基准、缺失升年级规则、或超出已配置学段时不强行猜测；提示补充或核实学籍。未确认大学等后续学段时不继续自动升级。
- 家长明确给出当日实际年级时优先使用；发生冲突则按家长校正记录新基准。发展阶段解释随实际年龄与学段调整。

## 虚构配置示例

以下仅展示结构，不能写入用户的正式档案。示例孩子在 2029-08-20 入小学一年级，采用每年 8 月 20 日升级、小学 6 年／初中 3 年／高中 3 年的规则：

```json
{
  "id": "child-1",
  "alias": "小星",
  "birth_date": "2023-04-12",
  "age_reference": null,
  "school_start": "2029-08-20",
  "school_baselines": [
    {
      "effective_date": "2029-08-20",
      "grade_index": 1,
      "promotion_day": "08-20",
      "stages": [
        {"name": "小学", "years": 6},
        {"name": "初中", "years": 3},
        {"name": "高中", "years": 3}
      ]
    }
  ]
}
```

首次只有“截至某日正在读小学三年级”也可从该日建立 `grade_index: 3` 基准，不必虚构入学日期；仍需确认升年级日期和学制。输入报告日期及私有配置后运行：

```text
python scripts/meeting_context.py 2030-08-20 --profile /private/FAMILY-profile.json --child-id child-1
```

对于该虚构示例，生日计算为 7 岁 4 个月、年级推算为小学 2 年级。多孩子须逐个用 `--child-id` 计算，并在同一会议报告中分别呈现每位孩子的上下文；不得只分析第一位。

## 家庭会议专用配置

本技能的配置和状态与睡前新闻独立保存，不能直接共享运行档案。首次设置还须询问通常参加会议的成员、可选会议频率／时间／时长、学期起止范围及学期提醒月份。会议计划不是实际召开证据。

`meeting_schedule` 可保存 `{weekday, time, planned_minutes}`，未提供留 null；这些是计划值，报告仍按实际会议日期、出席与时长记录。所有成员平等，不假设固定三口之家；称呼和代词按用户提供的信息使用。原规范的“爸爸／妈妈”栏目对应实际照顾者角色，多孩子逐人记录，缺席或未发言如实说明。

`semesters` 为带确切日期的列表，例如 `[{"key":"2030-term-1","start":"2030-01-10","end":"2030-04-20"}]`。配置列表为空或会议不在配置范围时，学期为未知／未覆盖，不能自动判为暑假；请补充范围后再汇总。支持多学期制，年度必需学期材料数量按当年已确认校历确定，不硬套两学期。范围不得重叠。`semester_reminder_months` 保存家长确认的提醒月份；仅在技能被调用时提醒，不创建后台自动化。

原规则的 9 月至次年 1 月、2 月至 7 月两学期制可以向用户提出作为选项，经确认后写成明确日期范围；不是所有家庭的事实。未传配置时脚本保留原版的日历参考结果，Agent 必须确认适用性后才能采用，不能以此绕过初始化。

三人家庭的年度奖项参考为 6–8 项、每人至少两项；人数变化时保留逐人平等覆盖原则，数量随人数及证据调整，证据不足注明缺口，不虚构获奖事例。家庭成员的独立同意、隐私和“不录”片段排除规则始终有效。
