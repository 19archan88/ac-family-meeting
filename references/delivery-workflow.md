# 先阅读、一轮完成

适用于默认MD+HTML交付。用户明确“先审阅”“只要文字”“不归档”或指定其他格式时优先遵从，不套用不适用的步骤。这里的提前阅读是完整正文，不是摘要或省略审计的草稿。

## 执行顺序

1. **开始计时。** 首次材料读取时，运行 `start`，回执放本次工作目录的 `.qa/<run>/delivery.json`。同批读取当前任务必要的规则、索引和材料；已读未变的规则不重复加载。完整阅读转写，历史与外部核查按SKILL.md的“无损提速”执行。
2. **正文就绪。** 完成分析、原话和隐私核对及事实核查，保存完整MD。原有同名报告修订前先备份；本轮不反复改写同一正文。运行 `ready` 记录正文哈希和就绪时间。归档摘要先写正文状态，最终交付说明报告文件与归档结果，不提前写“全部交付完成”。
3. **立即让用户阅读。** 使用可用的文件打开工具打开MD。Codex示例：`open_in_codex({target:{type:"file",path:"绝对路径.md"}})`。确认已展示后提示：“正文已可阅读，正在生成 HTML 并完成归档。”若返回`queued`、无法打开或工具不可用，则给MD链接，如实说明“正文已保存，可先通过链接阅读；侧栏打开请求已排队／未能自动打开，正在生成HTML”，不为此轮询或等待。不要把正式全文塞进进度消息，也不要在发送最终答复后声称继续后台制作。
4. **继续完成文件。** 无须用户再回复。从已核对的行动、来源及状态准备增量JSON，调用 `finish` 一次完成HTML构建、内嵌正文/哈希/离线资源检查、状态校验、备份和原子写入。只补格式时用 `--no-archive`，不重新统计会议。用户“不归档”且允许文件时保存到非正式输出目录并用该选项。
5. **自动打开最终HTML。** 所需文件生成、检查及归档成功后，使用文件打开工具打开本次最终HTML阅读版。Codex示例：`open_in_codex({target:{type:"file",path:"本次最终报告的绝对路径.html"}})`。本步在最终答复前执行，不再询问用户；不在答复结束后承诺后台打开。明确不归档时，在所需文件检查成功后执行；只要文字或尚待审阅时不额外生成HTML。若返回`queued`、打开失败或工具不可用，在最终交付中给HTML链接并如实说明排队或未能自动打开，不轮询、不将排队说成已展示。
6. **最终交付。** 对话展示与MD相同的完整正文和文件链接；仅用户明确只要文件时省去对话全文。真实说明已归档或失败待补。PDF/PNG默认不生成。失败保留MD，定位具体问题后修复重试；不能将脚本未验证的内容说成已验证。

需要修订正文时重新核对，并使用新回执标记新的正文哈希；已打开页面提示发生修订。不得为了通过哈希检查静默改动已交付的内容。

## 命令

以下路径为示意，替换为本次真实路径；Python只用标准库。计时文件不进入正式报告。

```text
python scripts/deliver_report.py start --receipt .qa/run/delivery.json
python scripts/deliver_report.py ready 档案/FM-2026-007-2026-10-17.md --receipt .qa/run/delivery.json
```

在`ready`之后先打开MD并发送进度提示，再运行：

```text
python scripts/deliver_report.py finish 档案/FM-2026-007-2026-10-17.md --receipt .qa/run/delivery.json --state 档案/STATE-latest.json --patch .qa/run/state-delta.json --family-archive 档案 --headline "忠实的阅读提要"
```

只构建/补格式，或用户明确不归档且允许文件：

```text
python scripts/deliver_report.py finish 输出/报告.md --receipt .qa/run/delivery.json --no-archive --onboarding-acknowledged
```

回执保存正文就绪墙钟耗时、构建检查耗时、归档耗时及实际状态。时间戳使用UTC便于计算；向用户展示日期时间按用户时区转换。正文墙钟耗时包括工具、用户等待等，不当作模型纯分析时间。回执不测最终聊天全文输出耗时，不能宣称是端到端总耗时。脚本不打开UI、不搜索、不作语义判定、不读取原始转写、不自动同意历史异常。

## 状态增量

在读取当前状态时计算其**原始文件字节**SHA-256，填写`base_sha256`。使用以下字段，只提供本次需要的增量，不重写整份STATE：

| 字段 | 用途 |
|---|---|
| `base_sha256` | 当前状态基准哈希；不匹配则停止，重新读取并合并 |
| `add` | 字典，键只能是`meetings/reports/actions/signals`，值为新增完整记录数组，沿用运行协议的字段 |
| `update` | 更新数组，每条含`collection`、`id`，以及可选`set`、`append`、`as_of` |
| `set` | 根级仅允许`updated_at`、`history_coverage_note`；不能替换整个集合 |
| `append_reminders` | 追加真实已提示的提醒记录，不创建后台调度 |
| `history_confirmation` | 仅存在真实用户确认时记录确认依据；不能为绕过异常自己填写 |

`update.set`只修改必要当前字段；修改行动/信号必须有`as_of`（实际证据日期），早于已保存较新证据则拒绝。旧日期补录用`append`追加`updates/reviews`等数组，不覆盖较新结果。已有数组只追加、不替换；同一事件不重复添加。报告内容修订用更大的`version`，并在修改MD前备份旧报告；仅补充历史上下文可追加`context_updates`而不假称重写过旧报告。需要更复杂的身份纠正或删改历史时按运行协议专门处理，不扩大通用脚本的覆盖权限。

示例是更新已有行动的**历史事件**，不是可直接写入家庭档案的数据：

```json
{
  "base_sha256": "读取当前状态时计算的SHA256",
  "update": [{
    "collection": "actions",
    "id": "已有的稳定行动ID",
    "append": {
      "updates": [{
        "meeting_id": "已确认的补录会议ID",
        "meeting_date": "2026-09-30",
        "event": "仅填写有来源的历史回顾，不填已排除内容"
      }]
    }
  }]
}
```

归档提交要求`reports`中存在与MD文件名一致的报告ID，且`artifacts`含已验证的MD和HTML路径。路径相对`STATE`所在档案目录的上一级目录，也可以使用绝对路径。新增周报还需对应唯一会议；月、学期、年度报告只新增`reports`，不新增会议。无历史状态时，只能按真实输入和已确认档案建立协议所列最小空集合，不能从示例生成历史。

脚本自动备份STATE到回执旁的`backups/`，写入前再次比对原文件；锁冲突或状态变化则停止。`delivery_commits`保存增量指纹及报告哈希，供相同增量重试时识别已提交，避免重复计数。确认结果后不要手工把增量换哈希再重复新增。失败时只修复报错原因，禁止删除锁或覆盖他人新状态来强行继续；确认锁确为已终止执行残留后才可清理。

## 验证范围

通用脚本验证审计模块的结构约定、文件一致性、离线资源、报告ID、重复计数、基准状态、补录不覆盖较新字段、备份与原子提交。它**不证明**分析深度、原话准确、隐私处理正确或事实来源可靠，这些须在正文就绪前完成；其他章节与来源完整性也仍按业务模块人工核对。日常模板未变不重复浏览器/PDF/PNG回归；改模板或遇到实际显示问题时按HTML规范检查受影响部分。

## 审计交付检查

`finish` 在 HTML 构建与状态提交之前调用 `check_report_content.py`。默认家长会议报告必须包含内容审计模块；月、学期、年度报告及家庭共读附件不强加周报模块，已有该模块时检查同一证据约定。缺项使回执标记失败，保留 MD，不写新的 HTML 或状态；修订正文后按既有流程建立新回执。

单独检查：`python scripts/check_report_content.py 报告.md`。固定表头及字段详见 [周报规则](weekly.md#审计表与证据约定)。无发现和材料不足可以如实说明，不编造审计条目。检查通过仅表示结构符合约定，不能证明引文和来源真实。低层 `build_report_html.py` 保留旧文无损补格式能力，不执行内容合规检查，不能把仅渲染成功当作新报告交付验收。
